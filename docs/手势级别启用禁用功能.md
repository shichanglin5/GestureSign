## 需求背景

### 现有启用/禁用层级

GestureSign 原有两个层级的启用/禁用控制：

| 层级 | 类型 | 粒度 |
|------|------|------|
| **IgnoredApp** | 应用级 | 屏蔽整个应用的所有手势 |
| **Command** | 命令级 | 启用/禁用单个命令 |

### 缺失的中间层

缺少 **Action（手势）级别** 的启用/禁用。用户无法针对某个应用禁用特定手势（例如：仅禁用浏览器中的"三指上滑"手势，但保留其他手势）。

### 禁用行为决策

禁用某应用的手势后，**回退到全局手势动作**。这与现有"禁用所有命令"的行为一致——当用户应用中找不到匹配的已启用 Action 时，系统自动查找全局应用中的同名手势。

## 设计方案

### 数据模型层

在 `IAction` 接口和 `Action` 类上添加 `IsEnabled` 属性：

```
启用/禁用层级关系：

IgnoredApp.IsEnabled (应用级)
  └── Action.IsEnabled (手势级)  ← 新增
       └── Command.IsEnabled (命令级)
```

**关键设计点**：
- 字段默认值为 `true`，确保旧数据反序列化时所有手势默认启用
- 实现 `INotifyPropertyChanged` 支持 UI 数据绑定
- `DeepCopy()` 正确复制 `IsEnabled` 值

### 业务逻辑层

在 `ApplicationManager` 的三个手势查找方法中添加 `a.IsEnabled` 过滤条件：

1. **`GetDefinedAction(gestureName, applications, useGlobal)`** — 主查询方法
2. **全局回退查询** — 当用户应用无匹配时查找全局手势
3. **`GetRecognizedDefinedAction(predicate)`** — 基于谓词的查询

过滤逻辑：
```
用户应用中查找 → 找到已启用的 Action → 返回
                → 未找到 → 全局应用中查找已启用的 Action → 返回
```

### UI 层

在 ControlPanel 的 Action 分组区域添加 ToggleSwitch 开关，位于手势图片下方、命令列表左侧。

### 数据模型变更

**IAction.cs**：
```csharp
public interface IAction : INotifyCollectionChanged
{
    bool IsEnabled { get; set; }  // 新增
    // ...其他属性不变
}
```

**Action.cs**：
```csharp
public class Action : IAction, ICloneable, INotifyCollectionChanged, INotifyPropertyChanged
{
    private bool _isEnabled = true;  // 默认 true，确保旧数据兼容

    public bool IsEnabled
    {
        get => _isEnabled;
        set
        {
            if (_isEnabled != value)
            {
                _isEnabled = value;
                PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(nameof(IsEnabled)));
            }
        }
    }

    public event PropertyChangedEventHandler PropertyChanged;
}
```

```csharp
// 1. GetDefinedAction 主查询 (行 333)
.Where(a => a.IsEnabled && a.GestureName == gestureName && a.Commands != null
    && a.Commands.Any(com => com != null && com.IsEnabled))

// 2. 全局回退 (行 342)
.Where(a => a.IsEnabled && a.GestureName == gestureName)
```

**AvailableActions.cs** — 事件处理：

```csharp
private void ActionToggleSwitch_Toggled(object sender, RoutedEventArgs e)
{
    var toggleSwitch = sender as ToggleSwitch;
    var groupItem = UIHelper.GetParentDependencyObject<GroupItem>(toggleSwitch);
    var group = groupItem?.Content as CollectionViewGroup;
    if (group?.Name is IAction action)
    {
        action.IsEnabled = toggleSwitch.IsOn;
        ApplicationManager.Instance.SaveApplications();
    }
}
```

应用级全部切换也改为操作 `action.IsEnabled`：

```csharp
private void ToggleAllActionsToggleSwitch_Click(object sender, RoutedEventArgs e)
{
    if (_isUpdatingToggleAllSwitch) return;  // guard 标志防止级联
    // ...
    foreach (var action in app.Actions)
    {
        action.IsEnabled = toggleSwitch.IsOn;
    }
    ApplicationManager.Instance.SaveApplications();
}
```

## Bug 修复：事件级联

### 问题现象

禁用单个手势后，该应用的**所有**手势都被禁用。

### 根因分析

事件链路形成了级联循环：

```
用户点击 Action ToggleSwitch
  → ActionToggleSwitch_Toggled()
    → SaveApplications()
      → ApplicationSaved 事件
        → GestureItemProvider.Update()
          → lstAvailableApplication_SelectionChanged()
            → 编程设置 ToggleAllActionsToggleSwitch.IsOn
              → MahApps 触发 Toggled 事件（编程赋值也触发）
                → ToggleAllActionsToggleSwitch_Click()
                  → 所有 action.IsEnabled = false  ← 全部禁用！
```

### 修复方案

#### 修复 1：Guard 标志防止编程赋值触发级联

```csharp
private bool _isUpdatingToggleAllSwitch;

// lstAvailableApplication_SelectionChanged 中：
_isUpdatingToggleAllSwitch = true;
try
{
    ToggleAllActionsToggleSwitch.IsOn = selectedApp.Actions.All(a => a.IsEnabled);
}
finally
{
    _isUpdatingToggleAllSwitch = false;
}

// ToggleAllActionsToggleSwitch_Click 中：
if (_isUpdatingToggleAllSwitch) return;  // 跳过编程触发
```

#### 修复 2：ToggleSwitch 移出 Button

原始实现中 ToggleSwitch 嵌套在 Button 内部，导致点击开关同时触发 `ActionButton_Click`（打开编辑对话框）。

将 ToggleSwitch 从 Button 的 `GestureImageGrid` 中移到 DockPanel 的独立位置，与 Button 平级。

### 经验总结

- MahApps `ToggleSwitch` 的 `Toggled` 事件在**编程赋值** `IsOn` 时也会触发，与原生 WPF CheckBox 的 `Checked`/`Unchecked` 行为不同
- 在事件驱动的 UI 中，`SaveApplications()` 触发的 `ApplicationSaved` 事件会导致 UI 刷新，形成意外的重入路径
- 交互控件不应嵌套在 Button 内部，避免事件冒泡引发多个处理器

## 序列化兼容性

| 场景 | 行为 |
|------|------|
| 旧版 `Actions.gsa`（无 `IsEnabled` 字段） | `_isEnabled` 字段默认值 `true`，所有手势默认启用 |
| 新版 `Actions.gsa`（含 `IsEnabled` 字段） | 正常序列化/反序列化 |
| `DefaultValueHandling.Include` | `IsEnabled=true` 时也写入 JSON |

序列化设置参考 `FileManager.SaveObject()`：
- `NullValueHandling.Ignore` — 跳过 null
- `DefaultValueHandling.Include` — 包含默认值
- `TypeNameHandling.Objects` — 写入类型名
