## 📋 需求概述

创建一个新的 GestureSign 插件："显示窗口"，实现类似 Windows Ctrl+Alt+Tab 的窗口选择器，支持灵活的过滤选项。

### 核心功能

1. **触发方式**：执行手势后显示窗口选择器
2. **过滤选项**（可配置，可组合）：
   - ✅ 只展示当前应用（当前激活窗口所属应用）
   - ✅ 只展示活动窗口（不展示隐藏的窗口和子窗口）
   - ✅ 只展示当前显示器
   - ✅ 只展示当前虚拟桌面
3. **显示内容**：
   - 使用 DWM API 显示窗口缩略图（完整预览）
   - 半透明背景遮罩
4. **交互方式**：
   - 键盘导航：方向键选择，Enter 确认，Esc 取消
   - 鼠标支持：点击缩略图直接激活

## 🔍 Windows 原生任务切换器性能分析

### Windows Ctrl+Alt+Tab 为什么这么快？

#### 1. DWM 缓存机制（两层缓存）

**第一层：Composition Buffer（合成缓冲区）- 我们能利用 ✅**

DWM 为每个窗口维护一个 **GPU 纹理**（Direct3D Surface）：
- 窗口每次重绘时，DWM 自动更新这个 GPU 纹理
- `DwmRegisterThumbnail` **直接引用**这个 GPU 纹理（零拷贝）
- 缩略图只是对 GPU 纹理的缩放操作（硬件加速）

**性能优势**：
- 窗口内容已经在 GPU 中，不需要 CPU 参与
- 多个缩略图并行渲染（GPU 并行度高）
- 窗口重绘时，缩略图自动更新（无需手动刷新）

**第二层：Iconic Thumbnails（静态缓存）- 我们不能直接利用 ❌**

主要用于最小化窗口的任务栏预览，与我们的实时缩略图是不同的 API 路径。

#### 2. GPU 加速渲染

| 技术 | 渲染方式 | 单缩略图耗时 | 并行度 |
|------|---------|-------------|--------|
| **DWM Thumbnails** (我们的方案) | GPU (Direct3D) | 5-10ms | 高（GPU 并行） |
| **PrintWindow + BitBlt** (备选方案) | CPU (GDI) | 50-150ms | 低（CPU 串行） |

**性能差距**：GPU 方案比 CPU 方案快 **10-30 倍**

## ⚡ 性能分析与优化

### 性能场景对比（使用 DWM GPU 加速）

| 过滤器配置 | 预期窗口数 | 缩略图创建时间 | 用户感知 |
|-----------|----------|----------------|----------|
| 只当前应用 | 2-5 | 10-50ms | ✅ 即时响应 |
| 当前显示器 | 10-20 | 50-200ms | ✅ 快速流畅 |
| 仅活动窗口 | 20-40 | 200-400ms | ✅ 流畅可接受 |
| 所有窗口 | 50-100+ | 500ms-1秒 | ⚠️ 可接受但有延迟 |

### 优化策略

**推荐实施**：
1. ✅ 智能默认配置（活动窗口 + 当前显示器）
2. ✅ DWM GPU 加速缩略图

**可选优化**（仅在需要时）：
3. ⚠️ 硬性限制最大窗口数（50 个）
4. ⚠️ 异步创建缩略图

**不需要实施**（GPU 加速已足够）：
- ❌ 虚拟化/延迟加载
- ❌ 位图缓存（DWM 本身有缓存）

### 性能验证标准

- ✅ 5 个窗口：< 50ms（即时）
- ✅ 10 个窗口：< 100ms（流畅）
- ✅ 20 个窗口：< 200ms（快速）
- ✅ 50 个窗口：< 500ms（可接受）

## ⚠️ 已知限制和风险

### 技术限制

1. **Windows 7+ 要求**：DWM API 仅在 Windows 7+ 可用
2. **HwndHost Airspace 问题**：原生 HWND 总在 WPF 内容之上
3. **性能考虑**：每个缩略图消耗 GPU 内存

### 潜在风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| DWM API 失败 | 缩略图无法显示 | 降级到图标+标题列表 |
| 窗口句柄失效 | 激活时崩溃 | 激活前验证窗口存在 |
| 内存泄漏 | 长时间运行后性能下降 | 确保 Dispose 正确调用 |
