## 问题现象

InertialScroll 模式下，垂直滑动时产生水平抖动，水平滑动时产生垂直抖动。缓慢滑动时尤为明显。

## 根因分析

原有 `ApplyJitterFilter` 是逐帧无状态过滤器：

```csharp
// 每帧独立判断次轴/主轴 < 阈值比时清零次轴
double ratio = minorDelta / mainDelta;
if (ratio < threshold) { /* 清零次轴 */ }
```

**局限性**：对缓慢滑动场景效果不足。单帧 delta 很小时，微小的次轴偏移也能超过阈值比（如主轴 2px、次轴 1px → ratio = 0.5 > 0.3），导致抖动无法过滤。

## 方案设计

用**按轴独立激活**机制替代逐帧无状态过滤：

1. 手势开始后，各轴独立累积原始位移（speedMultiplier 之前）
2. 某轴累积达到阈值后标记为**激活**，之后该轴正常滚动
3. 未激活的轴 delta 强制清零
4. 两个轴独立判断，可能都激活（斜向滑动）
5. 轴激活掩码在惯性阶段复用，保持一致性

### 与旧方案对比

| 特性 | ApplyJitterFilter | 轴激活阈值 |
|------|-------------------|-----------|
| 状态 | 无状态，逐帧判断 | 有状态，累积判断 |
| 判断依据 | 次轴/主轴比值 | 各轴独立累积位移 |
| 缓慢滑动 | 易误判 | 可靠 |
| 斜向滑动 | 按比例过滤 | 两轴独立激活 |
| 惯性阶段 | 每帧重新判断 | 复用手势阶段掩码 |

## 实现细节

### 数据模型

`InertialScrollSettings` 新增属性：

```csharp
/// 轴激活阈值 (0-100 像素)
/// 设为 0 禁用激活机制（两轴立即激活）
public double AxisActivationThreshold { get; set; } = 30.0;
```

### 执行器状态

`InertialScrollExecutor` 新增 6 个字段：

```
_activationAccumX / _activationAccumY  — 原始位移绝对值累积（用于激活判断）
_axisXActivated   / _axisYActivated    — 激活标志
_compensationX    / _compensationY     — 已变换 delta 累积（用于激活时补偿）
```

### 激活与补偿流程

```
ProcessFrame:
  1. 计算已变换 delta = rawDelta × speedMultiplier × 方向
  2. ApplyAxisActivation:
     a. 累积原始位移绝对值 → 判断是否达到阈值
     b. 累积已变换 delta → 补偿用
     c. 未激活：deltaX/Y = 0
     d. 首次激活：deltaX/Y = compensationX/Y（替换当帧 delta）
  3. ExecuteScroll(deltaX, deltaY):
     - WinUI 乘数等后续变换自然被应用
     - 补偿与正常滚动走同一路径，坐标系一致
```

### 状态生命周期

```
新手势开始（timeSinceLastGesture > NewGestureThresholdMs）
  → 重置激活状态（AxisActivationThreshold == 0 时立即激活）

手势进行中
  → 各帧累积判断激活

CaptureEnded → ResetGestureState()
  → 只重置 _accumulatedX/Y 和 _lastGestureTime
  → 保留轴激活掩码供惯性阶段使用

StartInertiaIfNeeded → OnInertiaTick
  → 复用 _axisXActivated/_axisYActivated 过滤

Reset()（完全重置，executor 回收时）
  → 清理所有字段
```

### 配置 UI

在 `ContinuousGestureConfigDialog` 的滚动方向 ComboBox 后增加 Slider：
- 范围 0-100，步长 5，默认 30
- 本地化：中文「方向激活阈值 (px)」/ 英文「Axis Activation (px)」

## Review 发现与修复

### 高优先级

**1. 惯性阶段轴掩码被提前清空**

`CaptureEnded` 调用顺序：先 `ResetGestureState()`（清空轴状态）再 `StartInertiaIfNeeded()`，导致惯性阶段两轴都被清零。

修复：`ResetGestureState()` 不再重置轴激活状态，仅在 `ProcessFrame` 新手势检测时重置。`Reset()` 仍清理所有字段。

**2. 补偿量坐标系不一致**

`_compensationX/Y` 最初累积原始位移（未乘 speedMultiplier、未应用方向映射），但直接并入 `_accumulatedX/Y`（已变换坐标系），导致补偿方向错误或量级突变。

修复：补偿改为累积已变换的 delta。

### 中优先级

**3. 激活当帧叠加尖峰**

激活时注入补偿 + 当帧 delta 继续进入 `ExecuteScroll`，产生突发脉冲。

修复：激活时用补偿量替换当帧 delta（`deltaX = _compensationX`），补偿已包含当帧，无重复计入。

**4. WinUI 路径补偿缺少乘数**

直接写 `_accumulatedX/Y` 绕过了 `ExecuteScroll` 中的 `WinUIScrollMultiplier`，WinUI/UWP 应用补偿偏小。

修复：补偿经 `ExecuteScroll` 正常路径，WinUI 乘数自然被应用。（与问题 3 同一修复）

## 配置兼容

- `MinorAxisThreshold`：保留属性用于反序列化旧配置（`ShouldSerializeMinorAxisThreshold() => false` 不再写出），代码逻辑不再使用
- `AxisActivationThreshold`：新属性，默认 30.0，旧配置缺失时自动取默认值

## V2 窗口比例判定 + 滞回状态机（可编码版规范）

> 背景：V1”轴激活阈值”存在结构性权衡：阈值偏大不跟手，阈值偏小抖动回归。
> 目标：做成更接近 macOS 体感的”起步快、稳定锁轴、斜向可释放、惯性一致”。
> 状态：**已评审通过，可编码。**

---

### 1. 窗口比例判定

基于最近 `windowMs`（固定 60ms）的原始位移（speedMultiplier 前）做判定：

```
sumX = Σ |rawDeltaX|    // 绝对值累积，避免来回抵消
sumY = Σ |rawDeltaY|
major = max(sumX, sumY)
minor = min(sumX, sumY)
ratio = major > 0 ? minor / major : 0
```

**关键决策**：用 `Σ |rawDelta|`（绝对值累积）而非 `Σ rawDelta`（带符号求和）。带符号求和在慢速来回抖动时 sum 趋零导致 ratio 异常。

**窗口缓冲实现**：`Queue<(DateTime timestamp, double absRawDeltaX, double absRawDeltaY)>`，每帧 while 循环淘汰过期样本（不用 LINQ），上限 maxSamples = 16 防止异常堆积。

### 2. 状态机

```
enum DirectionState { Undecided, LockX, LockY, Free2D }
```

| 状态 | 含义 | 抑制行为 |
|------|------|----------|
| `Undecided` | 起步判向中 | 缓冲 delta，不输出滚动 |
| `LockX` | X 为主轴 | `deltaY = 0`（硬抑制） |
| `LockY` | Y 为主轴 | `deltaX = 0`（硬抑制） |
| `Free2D` | 双轴放开 | 不处理 |

### 3. 状态切换逻辑

```
参数：
  ratEnter = NoiseRatio                          // 默认 0.25
  ratExit  = min(0.6, NoiseRatio + 0.10)         // 默认 0.35，上限 0.6
  startDistancePx = 8                            // 起步门槛
  windowMs = 60                                  // 窗口时长

Undecided:
  major < startDistancePx → 保持 Undecided
  major >= startDistancePx && ratio < ratEnter → LockX（若 sumX > sumY）或 LockY（若 sumY >= sumX）
  major >= startDistancePx && ratio >= ratEnter → Free2D

LockX / LockY:
  ratio > ratExit → Free2D
  否则 → 保持

Free2D:
  第一版不回切，保持 Free2D 直到手势结束
  （后续版本可加持续条件：连续 >=3 帧且 >=80ms 满足 ratio < ratEnter 才回切）
```

### 4. Undecided 阶段缓冲回补

**问题**：`Undecided` 阶段如果清零 delta 会产生起步空程（和 V1 同样问题）；如果直接通过则起步有抖动。

**方案**：缓冲 + 回补。

```
Undecided 阶段：
  1. 将当帧已变换 delta（经过 speedMultiplier/方向映射后）存入缓冲
  2. 不调用 ExecuteScroll
  3. 缓冲上限：windowMs 内 + maxSamples(16)

状态首次离开 Undecided（进入 LockX/LockY/Free2D）时：
  1. 遍历缓冲，按目标状态过滤每帧 delta：
     - LockX → 保留 deltaX，清零 deltaY
     - LockY → 保留 deltaY，清零 deltaX
     - Free2D → 保留两轴
  2. 将过滤后的 delta 逐帧回放到 ExecuteScroll（保证 WinUI 乘数等正确应用）
  3. 清空缓冲

手势结束仍在 Undecided 时：
  直接丢弃缓冲，不触发滚动（避免误触）
```

startDistancePx = 8px 大约 2-3 帧（触控板 ~125Hz），延迟 ~16-24ms，体感可忽略。

### 5. 惯性阶段

- 手势结束时（`CaptureEnded`）锁定当前 `DirectionState`
- `OnInertiaTick` 复用该状态做轴过滤，不重新判向
- `Undecided` 状态不启动惯性（等同手势未产生有效滚动）
- `ResetGestureState()` 不清空 `DirectionState`（与 V1 轴掩码同理）

### 6. 抑制策略

第一版硬抑制（`minorSuppression = 0.0`）：
- `LockX`：`deltaY = 0`
- `LockY`：`deltaX = 0`
- `Free2D`：不处理

抑制应用在已变换 delta 上（speedMultiplier/方向映射后），在 `ExecuteScroll` 之前。

### 10. 验证清单

- [ ] 极慢速垂直滑动：无水平漂移，起步不”卡”（Undecided 缓冲回补生效）
- [ ] 极慢速水平滑动：无垂直漂移
- [ ] 斜向滑动（~45°）：稳定进入 `Free2D`
- [ ] 快速切向（先竖后斜）：LockY → Free2D 平滑切换
- [ ] 惯性阶段：继承末态，不突发次轴
- [ ] WinUI 与非 WinUI：体感一致（回补经 ExecuteScroll 正常路径）
- [ ] NoiseRatio = 0.10：锁轴激进，斜向难解锁
- [ ] NoiseRatio = 0.50：锁轴宽松，大幅斜向才锁
- [ ] 手势结束仍在 Undecided（轻触不滑）：不产生滚动
- [ ] Direction = Vertical/Horizontal 时：V2 状态机不介入，保持原有行为
