## 问题现象

InertialScroll 模式下，垂直滑动时产生水平抖动，水平滑动时产生垂直抖动。缓慢滑动时尤为明显。

## 根因分析

原有 `ApplyJitterFilter` 是逐帧无状态过滤器：

```csharp
// 每帧独立判断次轴/主轴 < 阈值比时清零次轴
double ratio = minorDelta / mainDelta;
if (ratio < threshold) { /* 清零次轴 */ }
```

**局限性**：对缓慢滑动场景效果不足。单帧 delta 很小时，微小的次轴偏移也能超过阈值比（如主轴 2px、次轴 1px → ratio = 0.5 > 0.3），导致抖动无法过滤。

## 方案演进

### V1: 按轴独立激活阈值（已废弃）

每轴独立累积原始位移，达到绝对像素阈值后激活。存在结构性权衡：阈值大 → 起步不跟手，阈值小 → 抖动回归。

### V2: 窗口比例判定 + 滞回状态机（当前方案）

参考 macOS / libinput 标准做法，基于滑动窗口内原始位移比例判定方向，使用滞回双阈值防止边界抖动。

## 当前实现

### 1. 窗口比例判定

基于最近 60ms 的原始位移（speedMultiplier 前）做判定：

```
sumX = Σ |rawDeltaX|    // 绝对值累积，避免来回抵消
sumY = Σ |rawDeltaY|
major = max(sumX, sumY)
minor = min(sumX, sumY)
ratio = major > 0 ? minor / major : 0
```

**关键决策**：用 `Σ |rawDelta|`（绝对值累积）而非 `Σ rawDelta`（带符号求和）。带符号求和在慢速来回抖动时 sum 趋零导致 ratio 异常。

**窗口缓冲实现**：`Queue<(DateTime timestamp, double absRawDeltaX, double absRawDeltaY)>`，每帧 while 循环淘汰过期样本（不用 LINQ），上限 maxSamples = 16 防止异常堆积。

### 2. 状态机

```
enum DirectionState { Undecided, LockX, LockY, Free2D }
```

| 状态 | 含义 | 抑制行为 |
|------|------|----------|
| `Undecided` | 起步判向中 | 缓冲 delta，不输出滚动 |
| `LockX` | X 为主轴 | `deltaY = 0`（硬抑制） |
| `LockY` | Y 为主轴 | `deltaX = 0`（硬抑制） |
| `Free2D` | 双轴放开 | 不处理 |

### 3. 状态切换逻辑

```
参数：
  ratEnter = NoiseRatio                          // 默认 0.25
  ratExit  = min(0.6, NoiseRatio + 0.10)         // 默认 0.35，上限 0.6
  startDistancePx = 8                            // 起步门槛
  windowMs = 60                                  // 窗口时长

Undecided:
  major < startDistancePx → 保持 Undecided
  major >= startDistancePx && ratio < ratEnter → LockX（若 sumX > sumY）或 LockY
  major >= startDistancePx && ratio >= ratEnter → Free2D

LockX / LockY:
  ratio > ratExit → Free2D
  否则 → 保持

Free2D:
  不回切，保持 Free2D 直到手势结束
```

### 4. Undecided 阶段缓冲回补

**问题**：`Undecided` 阶段如果清零 delta 会产生起步空程；如果直接通过则起步有抖动。

**方案**：缓冲 + 回补。

```
Undecided 阶段：
  1. 将当帧已变换 delta（经过 speedMultiplier/方向映射后）存入缓冲
  2. 不调用 ExecuteScroll
  3. 缓冲上限：maxSamples(16)

状态首次离开 Undecided 时：
  1. 遍历缓冲，按目标状态过滤每帧 delta
  2. 将过滤后的 delta 逐帧回放到 ExecuteScroll（保证 WinUI 乘数等正确应用）
  3. 清空缓冲

手势结束仍在 Undecided 时：
  直接丢弃缓冲，不触发滚动（避免误触）
```

startDistancePx = 8px 大约 2-3 帧（触控板 ~125Hz），延迟 ~16-24ms，体感可忽略。

### 5. 惯性阶段

- 手势结束时（`CaptureEnded`）锁定当前 `DirectionState`
- `OnInertiaTick` 复用该状态做轴过滤，不重新判向
- `Undecided` 状态不启动惯性（等同手势未产生有效滚动）
- `ResetGestureState()` 不清空 `DirectionState`（惯性阶段需要）

### 6. 状态生命周期

```
新手势开始（timeSinceLastGesture > NewGestureThresholdMs）
  → 重置 DirectionState 为 Undecided，清空窗口缓冲和 Undecided 缓冲

手势进行中
  → 各帧更新窗口缓冲，状态机判定

CaptureEnded → ResetGestureState()
  → 只重置 _accumulatedX/Y 和 _lastGestureTime
  → 保留 DirectionState 供惯性阶段使用

StartInertiaIfNeeded → OnInertiaTick
  → 复用 DirectionState 做 ApplyDirectionSuppression

Reset()（完全重置，executor 回收时）
  → 清理所有字段
```

## 配置项

用户可配置：

| 属性 | 类型 | 范围 | 默认 | 说明 |
|------|------|------|------|------|
| `NoiseRatio` | double | 0.10-0.50 | 0.25 | 噪声轴比例阈值，值越小锁轴越激进 |

内部固定参数：

| 参数 | 值 | 说明 |
|------|-----|------|
| `ratEnter` | = NoiseRatio | 进入抑制阈值 |
| `ratExit` | = min(0.6, NoiseRatio + 0.10) | 退出抑制阈值 |
| `windowMs` | 60 | 判定窗口时长 |
| `startDistancePx` | 8 | 起步门槛 |

运行时 `NoiseRatio` 做 clamp 到 [0.01, 0.99]，防止极端配置值。

## Review 发现与修复

### V1 阶段

1. **惯性阶段轴掩码被提前清空**：`CaptureEnded` 先调 `ResetGestureState()` 再调 `StartInertiaIfNeeded()`，掩码被清空 → 从 `ResetGestureState` 中移除轴状态重置
2. **补偿量坐标系不一致**：补偿累积原始位移但并入已变换坐标系 → 改为累积已变换 delta
3. **激活当帧叠加尖峰**：补偿 + 当帧 delta 重复计入 → 激活时用补偿替换当帧 delta
4. **WinUI 路径补偿缺乘数**：直接写 `_accumulatedX/Y` 绕过 WinUI 乘数 → 补偿经 `ExecuteScroll` 正常路径

### V2 阶段

5. **Undecided 阶段 delta 处理**：缓冲 + 回补，保留起步跟手感
6. **Free2D 回切风险**：不回切 Lock，避免斜向滑动突然锁轴
7. **NoiseRatio 极端值**：运行时 clamp 到 [0.01, 0.99]

### 旧插件清理

8. **InertialScrollPlugin 已删除**：旧 CorePlugins 版本功能完全由 `InertialScrollExecutor`（连续手势内置执行器）替代
9. **历史动作静默失效**：PluginManager 在插件找不到时记录 warning 日志
