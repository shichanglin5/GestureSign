## 需求背景

### 原有问题（v3 及之前）

1. **连续手势仅限双指**：原实现将连续手势固定为 2 指滑动，不支持 3 指 / 4 指连续滑动
2. **模式单一**：连续滑动固定触发 InertialScroll 插件，无法为不同手指数配置不同行为
3. **配置存储不合理**：连续手势配置分散在 `IApplication.ContinuousGestureMode`（枚举）和 `IAction.ContinuousGesture`（Action 级别），数据模型不够灵活
4. **UI 分组不清晰**：动作列表没有区分"连续手势"和"普通手势"两种类型，底部操作按钮占用空间
5. **InertialScroll 路径冗长**：滚动执行需要经过 Action → Plugin 链路，但 ContinuousGesture Action 的创建 UI 已被移除，导致链路断裂

### 需求目标

- 支持 2/3/4 指连续手势，每种手指数独立配置
- 提供两种模式：**InertialScroll**（惯性滚动，内置执行）和 **Custom**（自定义，按方向配置命令）
- 配置存储提升到 Application 级别，使用 `ContinuousGestureSettings` 结构体（包含继承策略和配置列表）
- UI 改为两栏布局（连续手势 + 普通手势），各栏有 "+" 创建按钮
- 双指缩放通过 `PinchZoomInjector` 注入触摸输入，支持缩放+平移同时进行

## 功能设计

### 连续手势配置

每个应用（`IApplication`）拥有一个 `ContinuousGestureSettings` 对象，包含：

| 属性 | 类型 | 说明 |
|------|------|------|
| InheritBits | int | 继承策略位掩码（bit0=2指, bit1=3指, bit2=4指），默认 0b111 全部继承 |
| Configs | List\<ContinuousGestureConfig> | 配置列表 |

每个 `ContinuousGestureConfig` 配置项：

| 属性 | 类型 | 说明 |
|------|------|------|
| IsEnabled | bool | 是否启用（默认 true） |
| ContactCount | int | 手指数（2/3/4） |
| EnableZoom | bool | 是否启用缩放（仅 2 指有效） |
| ZoomSpeed | double | 缩放速度倍率 |
| ScrollMode | ContinuousScrollMode | 模式：InertialScroll 或 Custom |
| ScrollSettings | InertialScrollSettings | 惯性滚动参数（仅 InertialScroll 模式） |
| DirectionCommands | Dictionary<Gestures, List\<Command>> | 方向命令（仅 Custom 模式） |

### 继承策略

非全局应用可通过 `InheritBits` 控制各手指数是否继承全局配置：

- 默认全部继承（`0b111`）
- 如果 UserApp 有某手指数的配置（无论是否启用），该手指数不回退到全局
- 如果 UserApp 无某手指数的配置，且继承位为 1，则使用全局配置
- 如果继承位为 0，则不使用全局配置

### 两种模式

**InertialScroll 模式**：
- 触发器内置执行 `InertialScrollExecutor`，不经过 Action/Plugin 链路
- 支持完整的滚动参数配置（方向、加速因子、像素/滚动单位、反转、WinUI 检测等）
- 从 `InertialScrollPlugin` 提取核心逻辑，保持行为一致

**Custom 模式**：
- 每个方向（上/下/左/右）可配置独立的命令
- 命令通过 `CommandDialog` 配置，复用现有插件体系
- 触发时根据滑动方向查找对应命令，通过 `PluginManager.ExecuteCommands()` 执行
- 复用 PluginManager 的串行任务队列（`_lastActionTask`），保证与普通手势一致的 UserDisabled/Training 模式检查和异常处理

### 双指缩放

- 通过 `PinchZoomInjector` 使用 Windows Touch Injection API 注入两个虚拟触点
- 支持缩放（改变触点间距）和平移（移动触点中心）同时进行
- 触点坐标钳制在虚拟桌面范围内，防止超出屏幕导致 API 失败
- 注入失败时自动重置状态，允许重新触发

### UI 交互

```
┌─────────────────────────────────────┐
│ 连续手势               [继承][+]    │  ← 栏目标题
├─────────────────────────────────────┤
│ ☑ [2▾] ☑缩放 [惯性滚动▾] [设置][×] │  ← 每行一个配置，☑ 为启用开关
│ ☑ [3▾]       [自定义▾]   [设置][×] │
├─────────────────────────────────────┤
│ 普通手势                        [+] │  ← 栏目标题
├─────────────────────────────────────┤
│ 原有的 Action 列表（按手指数分组）  │
└─────────────────────────────────────┘
```

- 连续手势行在列表内直接创建，无需弹窗
- 每行有 ToggleSwitch 控制启用/禁用
- "继承"按钮仅在非全局应用时显示，弹出 `InheritConfigDialog`
- 点击"设置"打开 `ContinuousGestureConfigDialog`，根据模式展示不同设置面板
- 两个栏目平级放在同一个 `ScrollViewer` 内

## 架构设计

### 整体流程

```
用户触摸 → PointCapture
         → ContinuousGestureTrigger.PointCapture_PointCaptured()
         → GetEffectiveConfig(fingerCount)  // 从 Application 级别查找配置
         ├→ Zoom 检测（2指且 EnableZoom） → PinchZoomInjector（含平移）
         ├→ InertialScroll 模式 → InertialScrollExecutor.ProcessFrame()
         └→ Custom 模式 → ExecuteDirectionCommands() → PluginManager
```

### 配置优先级（GetEffectiveConfig）

```
1. 遍历 RecognizedApplication 中的 UserApp（跳过 IgnoredApp 和 GlobalApp）
   → 取第一个匹配的 UserApp（最高优先级），不继续遍历后续应用
   → 找到 ContactCount 匹配且 IsEnabled 的配置 → 返回
   → 找到 ContactCount 匹配但未 IsEnabled → 标记 userAppHasConfig=true
   → 记录 IsInherited(fingerCount)

2. 如果 userAppHasConfig=true → 返回 null（UserApp 有配置但禁用，不回退）
3. 如果 !userAppInherits → 返回 null（UserApp 明确不继承此手指数）
4. 查找 GlobalApp.ContinuousGestures 中 ContactCount 匹配且 IsEnabled 的配置 → 返回
5. 返回 null
```

注意：`ApplicationManager.Instance.RecognizedApplication` 在匹配到 UserApp 时**不包含 GlobalApp**，因此需要单独查找 `GetGlobalApplication()`。

### 层次依赖

```
Common (ContinuousGestureSettings, ContinuousGestureConfig, InertialScrollSettings)
  ↑
Daemon (ContinuousGestureTrigger, InertialScrollExecutor, PinchZoomInjector)
  ↑
ControlPanel (AvailableActions, ContinuousGestureConfigDialog, InheritConfigDialog)
```

`InertialScrollSettings` 定义在 Common 层而非 CorePlugins，避免 Common 依赖 CorePlugins 的反向引用。两者字段完全一致。

## 触发器重构

### ContinuousGestureTrigger

`GestureSign.Daemon/Triggers/ContinuousGestureTrigger.cs`

核心变更：

1. **`GetEffectiveConfig(int fingerCount)`** — 替代原 `GetEffectiveMode()`，从 Application 级别读取配置，支持 IsEnabled 检查和 InheritBits 继承策略。单独查找 GlobalApp（因为 RecognizedApplication 匹配 UserApp 时不含 GlobalApp）
2. **InertialScroll 路径** — 使用 `InertialScrollExecutor.ProcessFrame()` 内置执行，不经过 Action/Plugin 链路
3. **Custom 路径** — `ExecuteCustomMode()` 根据滑动方向调用 `ExecuteDirectionCommands()`，通过 `PluginManager.Instance.ExecuteCommands()` 执行（复用串行任务队列和模式检查）
4. **Zoom 检测** — 检测到缩放时将 deltaX/deltaY 传给 `PinchZoomInjector` 实现缩放+平移同时进行；注入失败时自动重置 `_isZooming` 状态
5. **多手指执行器缓存** — `Dictionary<int, InertialScrollExecutor>` 按手指数缓存执行器实例

### InertialScrollExecutor

`GestureSign.Daemon/Triggers/InertialScrollExecutor.cs`

从 `InertialScrollPlugin` 提取的核心滚动逻辑：

- `ProcessFrame(VelocityVector velocity, SystemWindow window, InertialScrollSettings settings)` — 每帧处理
- 包含速度乘数计算、累加器、WinUI/UWP 检测、抖动过滤
- 使用 `InputSimulator` 发送滚动事件，WinUI 应用使用 UI Automation `ScrollPattern`
- `Reset()` — 捕获结束时清理状态

## 双指缩放注入

### PinchZoomInjector

`GestureSign.Daemon/Triggers/PinchZoomInjector.cs`

使用 Windows Touch Injection API (`InjectTouchInput`) 注入两个虚拟触点模拟双指缩放：

**工作流程**：
1. `Start(center)` — 初始化两个触点（ID 0/1），间距 `InitialOffset=500`，发送 `POINTER_FLAG_DOWN`
2. `Update(distDelta, zoomSpeed, panDeltaX, panDeltaY)` — 更新间距（缩放）和中心点（平移），发送 `POINTER_FLAG_UPDATE`
3. `Stop()` — 发送 `POINTER_FLAG_UP`

**坐标钳制**（`ClampOffset()`）：
- 使用 `SystemInformation.VirtualScreen` 获取虚拟桌面范围
- 先钳制中心点 Y 到屏幕 Y 范围内（防止平移到上下边缘越界）
- 再钳制中心点 X 到屏幕 X 范围内（至少能容纳 MinOffset）
- 最后钳制 offset 确保两个触点 X 坐标不超出屏幕边界（留 1px margin）
- 防止坐标越界导致 `ERROR_INVALID_PARAMETER` (87)

**故障恢复**：
- `InjectTouchInput` 失败时，Windows 会取消所有活动触点
- 失败后立即设置 `_active=false`，`ContinuousGestureTrigger` 通过检查 `IsActive` 重置 `_isZooming`
- 下次触发时重新开始新的注入会话

### POINTER_INFO 结构体修正

`GestureSign.Daemon/Native/PointerInfo.cs`

修正了 `POINTER_INFO` 结构体中字段顺序的错误：

- **错误顺序**：PtPixelLocation → PtPixelLocationRaw → PtHimetricLocation → PtHimetricLocationRaw
- **正确顺序**：PtPixelLocation → PtHimetricLocation → PtPixelLocationRaw → PtHimetricLocationRaw

此错误导致 `InjectTouchInput` 在从零构建触摸数据时返回 `ERROR_INVALID_PARAMETER`。`PointerInputTargetWindow` 的"读取再回注"模式不受影响（因为其他字段都是默认值0）。

## 已知局限性

1. **每个手指数仅支持一个配置**：同一应用下同手指数不允许多个连续手势配置（通过 UI 限制强制）
2. **Custom 模式每个方向仅支持一个命令**：虽然数据模型支持 `List<Command>`，但 UI 目前只配置第一个命令
3. **InertialScrollPlugin 未废弃**：原 `InertialScrollPlugin` 仍作为插件存在，可通过普通手势 Action 触发。`InertialScrollExecutor` 是独立的提取版本
4. **旧字段保留**：`IApplication.ContinuousGestureMode` 和 `ZoomSpeed` 保留用于向后兼容的 JSON 反序列化，不再写入
5. **缩放仅限 2 指**：`EnableZoom` 在 3/4 指配置中自动隐藏，因为缩放依赖双指距离检测
6. **缩放触点坐标受屏幕范围限制**：当 offset 达到屏幕边界时缩放效果被钳制
