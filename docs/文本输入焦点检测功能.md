## 需求背景

用户希望针对"焦点在文本输入框"这一场景配置单独的手势。例如：

- 三指右滑 → 在文本输入框中触发 Enter 键
- 三指左滑 → 在文本输入框中触发 Backspace 键
- 相同手势在非文本输入框场景执行其他操作（如前进/后退）

### 核心挑战

| 框架类型 | 代表应用 | Win32 Caret | ClassName | UIA |
|---------|---------|-------------|-----------|-----|
| **原生 Win32** | 记事本、CMD | ✅ 可靠 | ✅ Edit | ✅ |
| **WPF** | 部分 .NET 应用 | ✅ 可靠 | ✅ TextBoxView | ✅ |
| **Chromium** | Edge, VSCode, Chrome | ⚠️ 隐藏 IME 光标 | ❌ Chrome_RenderWidgetHostHWND | ⚠️ 误报 |
| **Qt** | 微信 | ❌ 不使用 Win32 Caret | ❌ 自定义类名 | ⚠️ 部分支持 |
| **Scintilla** | Notepad++, 代码编辑器 | ✅ 可靠 | ✅ Scintilla | ✅ |

不同 UI 框架对 Win32 API 的支持程度差异巨大，无法用单一方法实现通用检测。

## 设计方案

### 新增匹配条件类型

在现有的 `MatchConditionType` 枚举中新增 `FocusedTextInput = 5`，作为窗口匹配规则的一个条件类型。

```csharp
public enum MatchConditionType
{
    ClassName = 0,
    Title = 1,
    ProcessName = 2,
    ProcessPath = 3,
    AUMID = 4,
    FocusedTextInput = 5  // 新增
}
```

### Value 格式

| Value | 含义 |
|-------|------|
| `"true"` | 焦点在文本输入框时匹配（Win32 检测） |
| `"true,uia"` | 焦点在文本输入框时匹配（Win32 + UIA 检测） |
| `"false"` | 焦点不在文本输入框时匹配 |
| `"false,uia"` | 焦点不在文本输入框时匹配（Win32 + UIA 检测） |

### 优先级

`FocusedTextInput` 的匹配优先级为 5（最低），因为需要跨线程检测，开销高于其他条件类型。

## 检测策略

采用**两级检测**策略：

### 第一级：ClassName + Caret 检测（~2μs）

1. 调用 `GetGUIThreadInfo` 获取目标窗口线程的 GUI 信息
2. 获取 `hwndFocus`（焦点控件句柄），调用 `GetClassName` 获取类名
3. 匹配已知文本输入框类名 HashSet
4. **Caret 辅助判据**：如果类名不匹配，但 `hwndCaret != 0` **且** `hwndCaret == hwndFocus`，判定为文本输入框

#### 已知文本输入框类名

```
Edit, RichEdit20W, RichEdit50W, RICHEDIT60W, RichEditD2DPT,
TextBox, RichTextBox, TextBoxView, _WwG, Scintilla, ConsoleWindowClass
```

另外支持 `RichEdit` 前缀匹配（覆盖版本变体）。

#### 为什么 Caret 必须等于 Focus

`hwndCaret != IntPtr.Zero` 只表示线程曾经创建过文本光标，不代表光标可见或焦点在文本框上：
- Chrome/Electron 为 IME 输入保持隐藏光标（`hwndCaret` 指向渲染子窗口，不等于 `hwndFocus`）
- 某些应用焦点离开文本框后光标句柄不立即清零

只有 `hwndCaret == hwndFocus` 时，才能确信光标确实在焦点控件上。

### 第二级：UIA 回退（~1-50ms，可选）

通过 `AutomationElement.FocusedElement` 检测：

1. `ControlType.Edit` → 文本输入框
2. `ControlType.Document` + `ValuePattern`/`TextPattern` → 可编辑文档
3. `ControlType.Custom` + 可键盘聚焦 + `ValuePattern` + 类名含 text/edit → 自定义文本控件

用户通过 UI 中的复选框控制是否启用此级。

### WindowMatcher 核心代码

```csharp
public static bool DetectFocusedTextInput(IntPtr hWnd, bool useUIA = false)
{
    // 获取目标窗口线程的 GUI 信息
    uint threadId = (uint)GetWindowThreadProcessId(hWnd, out _);
    if (!GetGUIThreadInfo(threadId, ref info))
        return useUIA && DetectTextInputViaUIA();

    // 第一级：ClassName + Caret 检测
    if (info.hwndFocus != IntPtr.Zero)
    {
        string? focusedClassName = GetWindowClassNameSafe(info.hwndFocus);
        if (!string.IsNullOrEmpty(focusedClassName) && IsTextInputClassName(focusedClassName))
            return true;

        // Caret 辅助判据：光标必须在焦点窗口上才可信
        if (info.hwndCaret != IntPtr.Zero && info.hwndCaret == info.hwndFocus)
            return true;
    }

    // 第二级：UIA 回退
    if (useUIA)
        return DetectTextInputViaUIA();

    return false;
}
```

### WindowInfoCache 缓存

```csharp
private bool? _isFocusedTextInput;
private bool? _isFocusedTextInputUIA;

public bool GetIsFocusedTextInput(bool useUIA)
{
    ref bool? cache = ref (useUIA ? ref _isFocusedTextInputUIA : ref _isFocusedTextInput);
    cache ??= WindowMatcher.DetectFocusedTextInput(_hWnd, useUIA);
    return cache.Value;
}
```

每次手势事件创建新的 `WindowInfoCache` 实例，不会跨事件缓存。同一事件内多次匹配同一窗口时复用缓存结果。

## UI 交互

### MatchConditionItem

选择"文本输入焦点"类型时：
- 隐藏 ValueTextBox（值自动设为 `"true"`）
- 隐藏 RegexCheckBox
- 显示 UIACheckBox（控制是否启用 UI Automation 回退）

### 推荐配置方式

将文本输入框规则配置为**应用内的优先级窗口规则**，而非全局规则。这样可以针对不同应用选择是否启用 UIA：

- 记事本、CMD 等原生应用：不勾选 UIA（Win32 检测即可）
- 微信等 Qt 应用：勾选 UIA（需要 UIA 辅助检测）
- Chrome/Edge：不建议使用 UIA（Chromium UIA Provider 误报率高）

支持一键复制所有信息到剪贴板。

## 已知局限性

### Chromium 应用（Edge, VSCode, Chrome）

- Win32 检测：`hwndCaret` 存在但不等于 `hwndFocus`，不会误报
- UIA 检测：Chromium UIA Provider 会把网页内容区域的元素（`<div contenteditable>` 等）报告为 `ControlType.Edit`，**导致严重误报**
- **建议**：不要对 Chromium 应用勾选 UIA

### Qt 应用（微信）

- Win32 检测：Qt 不使用 Win32 Caret API，`hwndCaret` 始终为零；焦点控件类名为 Qt 自定义类名
- UIA 检测：Qt 对 UIA 部分支持，效果取决于具体应用和 Qt 版本
- **建议**：勾选 UIA 并测试效果；如不可靠则用进程名/窗口类名组合条件替代

### WPF 应用

- Win32 检测：通常可靠，`TextBoxView` 类名在 HashSet 中
- 某些自定义控件可能需要 UIA 辅助

## 调试指南

### 使用 WindowDetailsDialog

1. 打开 ControlPanel → 选择应用 → 编辑窗口规则
2. 使用窗口选择器捕获目标窗口
3. 点击"详情"按钮查看完整信息
4. 重点关注：
   - **Focus ClassName**：焦点控件的类名
   - **Caret Handle**：显示 `(= Focus)` 或 `(≠ Focus)` 标注
   - **IsTextInput (Win32)**：不含 UIA 的检测结果
   - **IsTextInput (UIA)**：含 UIA 的检测结果

### 常见排查场景

| 现象 | 原因 | 解决方法 |
|------|------|----------|
| 始终匹配为文本输入框 | UIA 误报（Chromium 应用） | 取消勾选 UIA |
| 光标在闪但不识别 | Qt 应用不使用 Win32 Caret | 勾选 UIA 或改用组合条件 |
| 点击后才识别 | 焦点状态延迟更新 | 属正常行为，依赖应用的焦点管理 |
| 切换窗口后首次不识别 | 窗口激活与焦点设置有时序差 | 属正常行为 |
