# 问题背景与触发原因

## 背景

commit `d43be81`（"fix(Input): 修复 HID 多指触点解析不完整的问题"）修复了触摸板 Hybrid 模式下触点解析不完整的问题。修复后，每帧的 `InputPointList` 包含所有触点的完整数据（id、坐标、state），不再受 Finger 槽位数限制。

这个修复暴露了之前为绕过 Hybrid 限制而引入的一系列遗留架构的问题。

## Hybrid 修复前的架构假设

修复前，触摸板 HID 驱动在 Hybrid 模式下每次只报告部分触点（受 Finger 槽位数限制）。为了在不完整数据下正确识别手势，引入了以下机制：

1. **`TotalFingerCount`（来自 HID contactCount 字段）**：硬件报告的"真实"触点总数，但实际触点数据可能只有部分
2. **`_totalFingerCount`（PointCapture 内）**：通过 `Math.Max` 累积的历史最大手指数，弥补单帧数据不完整
3. **`MultiFingerDelay`**：手指落下后等待一段时间，让所有手指的数据通过多帧收集完毕
4. **`_pendingFirstPoints`**：delay 期间暂存的触点，等 delay 结束后一次性 StartCapture
5. **特征手指（`_featureFingerIds`）**：只追踪一个手指的轨迹用于手势匹配（因为不能保证所有手指数据完整）

## Hybrid 修复后的现状

修复后，每帧数据完整，不再需要上述绕行机制：

| 能力 | 修复前 | 修复后 |
|---|---|---|
| 每帧触点数据 | 部分（受 Finger 槽位限制） | 完整 |
| 实时手指数 | 需要 `TotalFingerCount` 字段 | `_activeContactIds.Count` 即可 |
| 手指数收集 | 需要 MultiFingerDelay 等待 | 每帧都有完整信息 |
| 触点追踪 | 只能追踪特征手指 | 所有手指都可追踪 |

## 遗留架构导致的具体问题

### 问题 1：4 指 Click/Tap 被误分类为 Trajectory

**诊断数据**：训练模式录制 8 个 4 指 click/tap，7 个被识别为 Trajectory。

| 块 | HasPrimaryButtonClick | ActiveContactIds | MaxPerFingerDistance | IsTapLike | 结果 |
|---|---|---|---|---|---|
| 1 | True | [0,1,2] | 45.4 | False | Trajectory |
| 2 | True | [0,1] | 32.4 | False | Trajectory |
| 3 | True | [2] | 38.6 | False | Trajectory |
| 4 | False | [] | 0 | True | **Tap** |
| 5 | False | [1] | 31.0 | False | Trajectory |
| 6 | True | [0,1] | 37.3 | False | Trajectory |
| 7 | True | [0,1,3] | 38.1 | False | Trajectory |
| 8 | True | [0,1] | 28.4 | False | Trajectory |

**根因**：`PointEventTranslator_PointUp` 在 `Capturing` 状态下，第一个手指 up 就触发 `EndCapture()`，不等其余手指释放。此时 `ActiveContactIds` 非空，Click/Tap 识别器全部不匹配。

**根本矛盾**：`Capturing` 状态的 up 处理逻辑为轨迹手势设计（一个手指抬起即结束），但 Click/Tap 需要所有手指释放才算完成。

### 问题 2：MultiFingerDelay 不再必要

delay 的原始目的是等待所有手指数据收集完毕。现在每帧数据已完整，delay 变成了不必要的延迟：

- **轨迹手势**：手指先落下（基本静止），超过移动阈值后才开始滑动。pending 阶段的 move 检查已经能处理这个，不需要 delay
- **Tap/Click**：有独立的时长阈值（如 tap 的 MaxDurationMs），在手指释放时计算 duration 判定即可
- **TipTap**：需要另一种进入机制（在 Capturing 状态下检测 fix+tap 模式），而不是依赖 delay 超时

### 问题 3：`_totalFingerCount` 冗余

`_activeContactIds` 实时维护当前在板上的触点集合。手指数 = `_activeContactIds.Count`，历史最大手指数可以在 `TrackAllPoints` 中追踪。不需要独立的 `_totalFingerCount` 字段和 `Math.Max` 累积逻辑。

### 问题 4：`_pendingFirstPoints` 随 delay 一起移除

`_pendingFirstPoints` 是 delay 机制的产物，delay 去掉后自然不需要。
