# 重构方案

## 目标

Hybrid 修复后，每帧触点数据完整，简化 PointCapture 状态机，移除不再必要的绕行机制。

## 改动清单

### 1. 去掉 MultiFingerDelay 机制

**移除内容**：
- `_multiFingerDelayTimer`（Timer 实例）
- `MultiFingerDelayCallback`
- `AppConfig.MultiFingerDelay` 配置项（或保留但默认 0 且不再使用）
- `PointEventTranslator_PointDown` 中 `if (multiFingerDelay > 0)` 分支

**替代逻辑**：
手指 down 时直接进入 `TryBeginCapture`（或 TipTap session），不再暂存到 pending。

### 2. 去掉 `_pendingFirstPoints` 机制

**移除内容**：
- `_pendingFirstPoints` 字段
- `_pendingTotalFingerCount` 字段
- `_pendingStartedAt` 字段
- `StartCaptureAfterDelay()` 方法（内联到 PointDown 流程）
- pending 阶段的 move 检查（`_pendingFirstPoints != null` 分支）
- pending 阶段的 up 检查（Case 1）

**影响**：PointDown 逻辑简化为——
```
手指 down
  ├─ 已在 Capturing → 更新手指数，return
  ├─ 已在 TipTap session → HandleTipTapPointDown
  └─ Ready → TryBeginCapture（直接进入 CapturingInvalid）
```

### 3. 用 `_activeContactIds` 历史最大值替代 `_totalFingerCount`

**当前问题**：`_totalFingerCount` 在多处通过 `Math.Max` 累积，与 `_activeContactIds` 的信息重复。

**方案**：
- 新增 `_peakFingerCount` 字段（或复用 `_totalFingerCount` 名称）
- 在 `TrackAllPoints` 中：`_peakFingerCount = Math.Max(_peakFingerCount, _activeContactIds.Count)`
- 移除 `_pendingTotalFingerCount` 和 `e.TotalFingerCount` 的依赖
- `FingerCount` 相关的使用场景仍用 `_peakFingerCount`，语义不变

### 4. 修复 Capturing 状态下 up 事件等待所有手指释放

**当前行为**（Case 2）：
```csharp
if (State == CaptureState.Capturing || (State == CaptureState.CapturingInvalid && allContactsReleased))
{
    EndCapture();  // 不检查 allContactsReleased
}
```

**新行为**：
```csharp
if (State == CaptureState.Capturing || State == CaptureState.CapturingInvalid)
{
    if (!allContactsReleased)
    {
        return;  // 等待所有手指释放
    }
    EndCapture();
}
```

**为什么不会影响轨迹手势**：
去掉 delay 后，轨迹手势的流程为：
1. 手指 down → `TryBeginCapture` → `CapturingInvalid`
2. 手指 move 超阈值 → `Capturing`
3. 手指 up → 如果还有手指在，等待；全部释放后 `EndCapture`

轨迹手势（如 3 指滑动）中，用户最终会抬起所有手指。等待全部释放不会改变结果，只是让 session 的结束时机延后几十 ms（手指不可能同时精确抬起）。对用户体验无感知影响。

## 新的状态机

```
Ready
  │
  ├─ finger down → TryBeginCapture → CapturingInvalid
  │                  或 TryBeginTipTapSession → TipTap
  │
  ├─ CapturingInvalid
  │    ├─ finger down → 更新 _peakFingerCount
  │    ├─ move 超阈值 → Capturing
  │    ├─ up（全部释放）→ EndCapture（判定 tap/click/trajectory）
  │    └─ up（部分释放）→ 等待
  │
  ├─ Capturing
  │    ├─ finger down → 更新 _peakFingerCount
  │    ├─ move → 记录轨迹
  │    ├─ up（全部释放）→ EndCapture（判定 trajectory）
  │    └─ up（部分释放）→ 等待
  │
  └─ TipTap session → 独立状态机
```

## TipTap 进入机制的调整

当前 TipTap 的进入依赖 MultiFingerDelay：
1. delay 期间新手指 down → `TryPromotePendingToTipTap()`
2. delay 超时 → `TryBeginTipTapSession()`

去掉 delay 后的方案：
- 在 `PointEventTranslator_PointDown` 中，`State == Ready` 时先尝试 `TryBeginTipTapSession`
- 在 `CapturingInvalid` 状态下，新手指 down 时尝试 promote 到 TipTap
- `TryBeginTipTapSession` 的条件检查保持不变（匹配已注册的 TipTap 配置）
